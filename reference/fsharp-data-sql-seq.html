lockForUpdate query

Full Usage: lockForUpdate query

Parameters:
    query : IQueryable<'T> - A SQLProvider query of a table's rows, joined ones too; not distinct, grouped, counted, aggregated or a union, and not a part of another query (a sub-query, a join's table) or a delete.

Returns: IQueryable<'T> The query, locking its rows when any executor runs it. A queryable that isn't a database query, such as a mock context's, comes back as it is; a SQLProvider query behind an in-memory step (Seq.map, then AsQueryable) is refused, as its rows couldn't be locked.
Type parameters: 'T

Marks a query to lock the rows it reads until the transaction ends, against lost updates: another transaction that locks, changes or deletes one of them waits until this one commits or rolls back.

Run it inside a transaction: a TransactionScope, with TransactionScopeAsyncFlowOption.Enabled in async code. Outside one the lock ends with the query. PostgreSQL, MySQL and Oracle write FOR UPDATE (PostgreSQL not the rows of a left-outer-joined table; Oracle not with skip, nor with take or head after a sort), Firebird FOR UPDATE WITH LOCK (one table, no joins), SQL Server the UPDLOCK and ROWLOCK table hints; SQLite, MS Access, DuckDB and ODBC have no row locks and refuse it. See "Locking rows" in the documentation.

query : IQueryable<'T>

A SQLProvider query of a table's rows, joined ones too; not distinct, grouped, counted, aggregated or a union, and not a part of another query (a sub-query, a join's table) or a delete.

Returns: IQueryable<'T>

The query, locking its rows when any executor runs it. A queryable that isn't a database query, such as a mock context's, comes back as it is; a SQLProvider query behind an in-memory step (Seq.map, then AsQueryable) is refused, as its rows couldn't be locked.

Example 

 use scope = new TransactionScope(TransactionScopeAsyncFlowOption.Enabled)
 let! order = query { for o in ctx.Main.Orders do where (o.OrderId = id); select o } |> Seq.lockForUpdateHeadAsync
 order.Freight <- order.Freight + 1m
 do! ctx.SubmitUpdatesAsync()
 scope.Complete()
